# 拼单策略方法论（party-strategies.md）

> 麦拼单的决策逻辑。Agent 执行拼单任务时按本文件组织思路；
> 所有涉及金额的结论，最终以 `calculate-price` 返回为准。

## 一、需求解析：把一句话变成约束

用户输入通常是口语，先归成四类约束：

| 约束 | 例子 | 归成 |
|---|---|---|
| 人数 | 「5 个人」「咱部门 8 个」 | N |
| 预算 | 「人均 35」「总共不超过 200」 | 人均 B = 总预算 / N |
| 忌口/偏好 | 「有人不吃辣」「都要可乐」 | avoid 列表 / prefer 列表 |
| 渠道 | 「送到公司」「下楼自取」 | orderType=2 外送 / orderType=1 到店 |

**缺信息先问再动手**：地址没给 -> 问；人数预算缺 -> 用默认值并声明假设。
**忌口是硬约束**：过滤后无解就明说，不偷偷替换。

## 二、门店选择：拼单选「交集店」

多人拼单的门店不是「最近」，是**大家都方便**：

1. `query-nearby-stores` 按发起地址拉列表；
2. 外送场景先 `delivery-query-addresses` 确认收货地址
   （就是拼单集合点，通常是公司），再 `delivery-query-stores`；
3. 多家候选时展示店名 + 类型（得来速/外送/到店），让用户选，
   **不替用户决定门店**。

## 三、菜单与券：先券后菜

顺序有讲究——**先拿券，再点菜**，因为券决定了什么菜值得点：

1. `query-store-coupons`：这是**唯一返回 couponId** 的接口，同时给出
   每张券适用哪些商品编码。先把「满减门槛」和「单品券」摸清；
2. `query-my-coupons`：补充我账户里已有的券（无 couponId，仅参考）；
3. `query-meals`：按**当前渠道**取菜单。到店/外送编码不同，取错算价返回
   `price:0` 空列表——那不是下架，是编码错；
4. 单人点餐场景才考虑 `auto-bind-coupons`（写操作，需确认）；拼单默认不领，
   在方案里注明「可领券 X，确认后领取」。

## 四、组合规划：约束满足，不追求最优解

`pick_combo` 的逻辑（scripts/mcd.py）：

1. 按 avoid 过滤菜单，记录被过滤名单（要展示给用户，体现忌口被尊重）；
2. 主食优先：prefer 命中 > 价格最接近人均预算 45% 的；
3. 小食最多花剩余的 60%，饮料最多 40%——保证组合均衡不头重脚轻；
4. 主食超预算 -> 返回无解，**明说原因，不硬凑**。

券建议（`build_party_plan`）：取「门槛 ≤ 原价合计」中优惠最大的一张。
多券叠加属于组合优化，MVP 不做——把单张最优券讲明白，比堆复杂度靠谱。

## 五、核价与方案：calculate-price 是唯一法官

- 每个候选方案**各跑一次** `calculate-price`，以返回值排序选最优；
- 本地算的「原价合计/优惠/实付」只是预估，展示时标注
  「金额以 calculate-price 实测为准」；
- `discount` 字段是相对券的原价口径，**不当「省了多少」宣传**；
- 特调（去冰、换燕麦奶 +¥2）可以传，但 `calculate-price` 不回显结果——
  只确认不报错，不对用户断言「已生效」。

## 六、AA 拆单：两种模式

| 模式 | 公式 | 适用 |
|---|---|---|
| 按实付均摊 | (原价合计 - 券优惠) / N | 默认，拼单最常用 |
| 按原价均摊 | 原价合计 / N | 有人请客/券是某人账号的场景，另议 |

输出精确到分；除不尽的零头归发起人（拼单惯例，需在方案里注明）。

## 七、写操作红线（不可逾越）

以下操作**必须**先向用户列明（门店、餐品明细、金额、券、配送信息），
获得**明确同意**后才执行：

- `auto-bind-coupons`（领券，改变账户券状态）
- `create-order`（下单，真实扣款）
- `cancel-order`（取消订单）
- `party-order-create` / `mall-create-order` / `draw-lottery`（花钱/耗积分）

外送单 `create-order` 支持 `remark`（≤50 字）：免费配件
（番茄酱/糖/胡椒粉）写这里；到店单没有备注入口，引导到店索取。

## 八、能力边界（不知道就说不知道）

- **没有库存接口**：「这家店还有货吗」MCP 无法回答；
- **没有天气接口**：「下雨吗」无法回答；
- **营业状态**只能通过 `now-time-info` + `campaign-calendar` 间接推断，
  最终以门店实际为准。
